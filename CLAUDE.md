# GDPval Synthetic Task Generation Pipeline

## Project Goal

Build a synthetic data pipeline that generates professional tasks indistinguishable from real GDPval (OpenAI's 220-task benchmark across 44 occupations). Target: SFT dataset for training domain-proficient agents.

## Core Architecture: Answer-First Design

The reference answer is designed **synchronously** with the task prompt and rubric, not generated by having a model "solve" the task later.

```
CanonicalScenario (seed data + pinned facts)
    ↓
ReferenceAnswer blueprint (structured, deterministic)
    ↓
TaskCandidate (prompt + rubric + blueprint)
    ↓
Deterministic rendering → .docx / .xlsx / .md / .pdf
```

Key insight: The prompt writer is told "here is what the reference answer will look like" so the task requirements match the deliverable exactly.

## Key Design Decisions

1. **Blueprint-based rendering**: ReferenceAnswer contains `SectionBlueprint` / `SheetBlueprint` / `CellBlueprint` — structured data rendered by deterministic code (openpyxl, python-docx) into real files with live formulas.
2. **Seed-driven diversity**: Each occupation uses real seeds (CourtListener for lawyer, SEC EDGAR for financial, GitHub issues for SWE) so canonical facts are grounded.
3. **3-stage synthesis**: Enrichment → Prompt Writer → Rubric Generator (+ Narrative Generator for docx/md content).
4. **Quality funnel**: Hard validators → Embedding dedup (BAAI/bge-small-en-v1.5, threshold 0.85) → Realism critic → Solvability critic.

## How to Run

```bash
# Install deps
uv sync

# Run pipeline batch (n=10, grid seed=45)
uv run python -m pipeline.orchestrator --batch-size 10 --grid-seed 45

# Verify alignment metrics
uv run python pipeline/verify/gdpval_alignment.py

# Inspect a task
python scripts/inspect_seeds.py --task-id sc_xxx
```

## LLM Configuration

Uses Mimo API (`mimo-v2.5-pro`) via OpenAI-compatible endpoint. Config in `pipeline/config.py`.

## Current Status (as of latest commit)

- **12 accepted tasks** with real deliverables
- **Acceptance rate**: ~75% through quality funnel
- **Known gaps vs GDPval targets**:
  - Exact-match rubric items: 6.7% (target ~73% of tasks)
  - Input attachment rate: 25% (target ~57%)
  - Prompt length median: 2458 chars (target ~2024)
  - PDF rendering requires LibreOffice (not installed on current server)

## Key Files

| File | Purpose |
|------|---------|
| `pipeline/scenario/synthesis.py` | Prompt writer + rubric generator + narrative generator |
| `pipeline/scenario/builders.py` | Per-occupation canonical scenario builders |
| `pipeline/scenario/reference_answer.py` | Blueprint models (ReferenceAnswer, SectionBlueprint, etc.) |
| `pipeline/artifacts/renderer.py` | Deterministic deliverable rendering |
| `pipeline/artifacts/input_renderer.py` | Input attachment rendering |
| `pipeline/orchestrator.py` | Main pipeline orchestration |
| `pipeline/verify/gdpval_alignment.py` | Automated alignment metrics |

## Deliverable Formats

- `.xlsx` (financial: DCF, variance analysis)
- `.docx` (legal: motion, brief, contract redline; financial: credit memo)
- `.md` (SWE: code review, incident postmortem, design doc)
- `.pdf` (legal docs rendered via LibreOffice from docx)

## File Layout

```
data/accepted/          # Accepted task JSONs + input attachments
data/deliverables/      # Rendered deliverable files
data/gdpval_reference/  # Real GDPval tasks for comparison
pipeline/scenario/      # Core generation logic
pipeline/artifacts/     # Rendering code
pipeline/critic/        # Quality critics
pipeline/validators/    # Hard validators
pipeline/verify/        # Alignment metrics
```
