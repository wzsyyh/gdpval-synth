# GDPval Synthetic Task Generation Pipeline

## Project Goal

Build a synthetic data pipeline that generates professional tasks indistinguishable from real GDPval (OpenAI's 220-task benchmark across 44 occupations). Target: SFT dataset for training domain-proficient agents.

## Core Architecture: Answer-First Design

The reference answer is designed **synchronously** with the task prompt and rubric in a single LLM call, not generated by having a model "solve" the task later.

```
Seed (real public data)
    ↓
Unified Generation (single LLM call)
    ↓
TaskCandidate { prompt + rubric + reference_answer blueprint }
    ↓
Hard quality validation + LLM consistency check
    ↓
Deterministic rendering → .docx / .xlsx / .md / .pdf
```

Key insight: The LLM reads the full seed material and designs the task, answer, and rubric together, ensuring all facts come from the seed and the rubric is verifiable against the answer.

## Key Design Decisions

1. **Unified generation**: Single LLM call reads full seed → outputs structured `UnifiedTask` with prompt, answer blueprint, and rubric. All facts must come from the seed material.
2. **Blueprint-based rendering**: ReferenceAnswer contains `SectionBlueprint` / `SheetBlueprint` / `CellBlueprint` — structured data rendered by deterministic code (openpyxl, python-docx) into real files with live formulas.
3. **Seed-driven diversity**: Each occupation uses real seeds (CourtListener for lawyer, SEC EDGAR for financial, GitHub issues for SWE) so canonical facts are grounded.
4. **Quality gate**: Hard validators (6 deterministic checks: prompt length, rubric count, score distribution, vague language, attachment quality, answer content) + LLM-based consistency validation.
5. **Per-occupation system prompts**: Independent prompts for lawyer, financial_analyst, software_engineer to prevent cross-domain interference.

## How to Run

```bash
# Install deps
uv sync

# Run pipeline batch (n=10, grid seed=45)
uv run python -m pipeline.orchestrator --batch-size 10 --grid-seed 45

# Verify alignment metrics
uv run python pipeline/verify/gdpval_alignment.py

# List all seeds
uv run python scripts/inspect_seeds.py

# Validate deliverables
uv run python scripts/validate_deliverables.py
```

## LLM Configuration

Uses Mimo API (`mimo-v2.5-pro`) via OpenAI-compatible endpoint. Config in `pipeline/config.py`.

## Current Status (as of latest commit)

- **96 accepted tasks** with real deliverables (lawyer: 34, financial: 24, SWE: 38)
- **Acceptance rate**: ~91% (96/105) through hard quality + consistency validation
- **Key deliverable types**:
  - Lawyer: `legal_memo` (docx/pdf)
  - Financial: `credit_memo`, `investment_memo` (docx)
  - SWE: `code_review`, `design_doc` (md)
- **Known limitations**:
  - Financial tasks are qualitative-only (credit/investment memos) due to LLM number hallucination on XBRL data
  - Difficulty is heuristic (seed selection criteria + LLM time guidance), not empirically validated
  - PDF rendering requires LibreOffice

## Key Files

| File | Purpose |
|------|---------|
| `pipeline/scenario/synthesis.py` | Unified generation: single LLM call produces prompt + answer blueprint + rubric |
| `pipeline/scenario/reference_answer.py` | Blueprint models (ReferenceAnswer, SectionBlueprint, etc.) |
| `pipeline/artifacts/renderer.py` | Deterministic deliverable rendering |
| `pipeline/artifacts/input_renderer.py` | Input attachment rendering |
| `pipeline/validators/hard_quality.py` | Hard quality validators (6 deterministic checks) |
| `pipeline/validators/llm_consistency.py` | LLM-based consistency validation |
| `pipeline/orchestrator.py` | Main pipeline orchestration |
| `pipeline/verify/gdpval_alignment.py` | Automated alignment metrics |

## Deliverable Formats

- `.docx` (legal: legal_memo; financial: credit_memo, investment_memo)
- `.md` (SWE: code_review, design_doc)
- `.xlsx` (financial: investment_memo with live formulas)
- `.pdf` (legal docs rendered via LibreOffice from docx)

## File Layout

```
data/accepted/          # Accepted task JSONs + input attachments
data/deliverables/      # Rendered deliverable files
data/gdpval_reference/  # Real GDPval tasks for comparison
pipeline/scenario/      # Core generation logic
pipeline/artifacts/     # Rendering code
pipeline/validators/    # Hard validators + consistency check
pipeline/verify/        # Alignment metrics
```
