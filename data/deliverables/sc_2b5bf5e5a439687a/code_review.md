# Code Review Summary — PR #38758: Deprecate TF + JAX

## Overview

PR #38758, titled "Deprecate TF + JAX", was merged into the huggingface/transformers repository on 2025-06-11T16:28:06Z. This pull request represents a major deprecation effort that removes TensorFlow (TF) and JAX/Flax framework support from the Transformers library. The change touches 121 files across the codebase, with only 27 lines added (primarily deprecation notices and updated documentation) and 50,030 lines deleted, reflecting the comprehensive removal of TF and JAX model implementations, tests, and associated utilities. This is one of the largest single deprecation events in the repository's history, signaling the project's full commitment to a PyTorch-centric architecture going forward.

## Motivation and Context

The decision to deprecate TF and JAX support was driven by the unsustainable maintenance burden of supporting three separate deep learning frameworks within a single library. Maintaining parallel implementations for PyTorch, TensorFlow, and JAX required triple the testing infrastructure, triple the documentation, and triple the review effort for every model addition or architectural change. Over time, the Transformers community has increasingly consolidated around PyTorch as the primary framework, with the vast majority of users, contributors, and downstream projects relying on PyTorch-based workflows. The PR description captured this moment succinctly with the phrase "The time has finally come :gun: :tumbler_glass:", acknowledging both the inevitability and the finality of this deprecation decision. The emoji references suggest the team viewed this as a long-anticipated milestone rather than a reactive measure.

## Scope of Changes

The scope of PR #38758 is enormous by any standard. With 121 files changed, 27 additions, and 50,030 deletions, the change is overwhelmingly characterized by removal rather than new code introduction. The 27 added lines likely consist of deprecation warnings, updated import guards, and documentation notes directing users to PyTorch alternatives. The 50,030 deleted lines span multiple categories of code: TF and JAX model implementations (e.g., modeling_tf_*.py and modeling_flax_*.py files), framework-specific test suites (e.g., test_modeling_tf_*.py and test_modeling_flax_*.py), configuration classes tied to TF/JAX backends, and documentation sections covering TF/JAX usage patterns. This represents a complete excision of two framework backends from the library.

## Impact Analysis

The deprecation has significant implications for several stakeholder groups. Users who rely on TensorFlow-based model loading and inference via classes like TFAutoModel or TFPreTrainedModel will find these interfaces removed in the version following the deprecation. They must migrate to the PyTorch equivalents (AutoModel, PreTrainedModel) before upgrading. Similarly, users relying on JAX/Flax-based workflows using classes like FlaxAutoModel or FlaxPreTrainedModel face the same migration requirement. CI/CD pipelines that include TensorFlow or JAX test jobs will fail if those jobs reference the now-deleted test files, requiring immediate pipeline updates. Third-party libraries that import from transformers.tf or transformers.flax modules will break upon upgrading to the post-deprecation version. These downstream integrators must coordinate their releases with the Transformers deprecation timeline.

## Migration Guidance

Teams affected by this deprecation should follow a structured migration plan. First, replace all TensorFlow-based model usage with PyTorch equivalents: swap TFAutoModel.from_pretrained(...) calls with AutoModel.from_pretrained(...) and ensure PyTorch model weights are available for the target models. Second, audit all import statements for patterns like from transformers import TFAutoModel, from transformers import FlaxAutoModel, or any transformers.tf.* / transformers.flax.* imports, and replace them with their PyTorch counterparts. Third, remove tensorflow, tf-keras, jax, jaxlib, and flax from your project requirements files (e.g., requirements.txt, pyproject.toml) if they were only present for Transformers integration. Fourth, update CI/CD pipeline configurations (e.g., .github/workflows/ files, Jenkinsfile, GitLab CI) to remove any test jobs that specifically run TF or JAX test suites against the Transformers library.

## Risk Assessment

Several risks accompany this large-scale deprecation. Users who have pinned older versions of Transformers in their dependencies and later decide to upgrade will encounter breaking changes, as the TF and JAX interfaces they depend on will no longer exist. The loss of multi-framework interoperability means that model checkpoints trained in TensorFlow can no longer be directly loaded into Transformers without conversion, and users must rely on external conversion tools. There is also a risk of orphaned model cards and documentation pages that still reference TF or JAX usage patterns, potentially confusing users who encounter outdated guides. The repository maintainers should audit existing documentation and model cards to ensure they are updated or clearly marked as deprecated.

## Recommendations

The Transformers team should implement a clear communication strategy for this deprecation, including release notes prominently highlighting the removal, blog posts explaining the rationale, and direct outreach to major downstream integrators. A deprecation period of at least one major version cycle should be maintained to give users time to migrate, with clear warnings in the preceding version. Downstream library maintainers should be notified through GitHub issues or community forums. For model cards and documentation, the team should add deprecation banners to any remaining TF/JAX references and provide links to the official migration guide. Overall, the deprecation is a necessary step toward reducing complexity and improving the maintainability of the Transformers library, and clear communication will be key to minimizing disruption.
